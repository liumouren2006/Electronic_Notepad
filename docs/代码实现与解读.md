### 0.2 一条数据在系统里的生命周期

```text
用户输入
  → Event（id/title/note/due/priority/tags/attachments/page_layout）
  → EventList（priority 就是链表位置）
  → Repository（业务校验、撤销快照、写盘）
  → Store（events.json + events.json.bak + backups/）
  → 各端读取同一份 JSON
  → 可选：打包为 .mjnote → 云同步 → 另一台设备合并
```

关键不变量：

- `priority` 永远等于链表中的 1 基位置；
- `events.json` 是 UTF-8 文本，PC 与 Android 字段一一对应；
- 写盘先写临时文件，再原子替换，任何时刻磁盘上至少有一份完整数据；
- 删除是“真删除 + 墓碑同步”，而不是给记录打一个隐藏标记。

## 1. PC 端核心算法

### 1.1 数据模型：Event 与 Attachment

`src/core/model.hpp` 用两个结构体描述全部业务数据。`Event` 的字段覆盖作业要求和后续扩展：

```cpp
struct Event {
    std::string id;              // 8 位随机十六进制
    std::string title;
    std::string note;            // Markdown 源文本
    std::optional<std::time_t> due;
    int priority = 1;
    bool done = false;
    std::optional<std::time_t> done_at;
    std::vector<std::string> tags;
    std::vector<Attachment> attachments;
    std::optional<std::time_t> created_at;
    std::optional<std::time_t> updated_at;   // 云同步比较依据
    int remind_before = 0;                   // 提前分钟
    bool system_notify = false;
    std::string ringtone;
    std::optional<std::time_t> snooze_until;
    std::optional<std::time_t> last_reminded_at;
    std::string color;
    std::string icon;
    std::string page_layout;     // 页面布局 + 墨迹 JSON
};
```

设计要点：

1. **时间统一用 `time_t` 秒**，序列化为本地时区的 `yyyy-MM-ddTHH:mm:ss`，不带时区后缀。PC 和 Android 都按本地时间解释，避免跨端差 8 小时。
2. **可选字段用 `std::optional`**。`due` 为空表示“无期限”，`done_at` 为空表示未完成，`updated_at` 为空时在 `from_json` 中回退到 `created_at`。
3. **`updated_at` 是同步的核心**。任何修改都必须刷新它，否则另一台设备会认为本地版本更新。
4. **`page_layout` 是字符串而不是结构体**。它由页面编辑器生成 JSON，核心层不解析，避免核心依赖 GUI 的图层细节。

`Event::from_json` 做防御式解析：字段缺失、类型错误、标签是字符串而不是数组，都能降级处理：

```cpp
Event Event::from_json(const json& j) {
    Event e;
    if (!j.is_object()) return e;
    e.id = j.value("id", "");
    e.title = trim(j.value("title", ""));
    e.note = j.value("note", "");
    e.due = opt_time(j, "due");
    e.priority = std::max(1, j.value("priority", 1));
    // tags 既接受数组，也接受 "课程, 截止" 字符串
    // attachments 只接受带非空 path 的对象
    // created_at/updated_at 缺失时补当前时间
    if (e.id.empty()) e.id = uuid8();
    return e;
}
```

### 1.2 优先级单向链表：EventList

作业要求“插入后原位置及之后顺延”。最自然的实现是把优先级直接编码成链表位置：第 1 个节点就是 P1，第 n 个节点就是 Pn。

`src/core/elist.hpp` 定义了节点和迭代器：

```cpp
class EventList {
public:
    struct Node {
        Event event;
        Node* next = nullptr;
    };
    // begin()/end() 让范围 for 可以直接遍历
    Event& append(Event event);
    Event& insert_at(int pos, Event event);
    std::optional<Event> remove(const std::string& id);
    bool move_to(const std::string& id, int pos);
    bool move_by(const std::string& id, int delta);
    void reindex();
private:
    Node* head_ = nullptr;
    Node* tail_ = nullptr;
    size_t size_ = 0;
};
```

**插入算法**（`EventList::insert_at`）：

```cpp
Event& EventList::insert_at(int pos, Event event) {
    int total = (int)size_;
    if (pos < 1) pos = 1;
    if (pos > total + 1) pos = total + 1;

    Node* prev = nullptr;
    Node* cur = head_;
    for (int i = 1; i < pos && cur; ++i) {
        prev = cur;
        cur = cur->next;
    }
    Node* node = new Node{std::move(event), cur};
    if (prev) prev->next = node;
    else head_ = node;
    if (!node->next) tail_ = node;
    ++size_;
    reindex();          // 从 1 开始重新编号
    return node->event;
}
```

时间复杂度 O(n)，空间 O(1)。`reindex` 是保证不变量的关键：

```cpp
void EventList::reindex() {
    int p = 1;
    for (Node* n = head_; n; n = n->next) {
        n->event.priority = p++;
    }
}
```

**删除**要同时处理头节点、尾节点和中间节点：

```cpp
std::optional<Event> EventList::remove(const std::string& id) {
    Node* prev = nullptr;
    Node* cur = head_;
    while (cur) {
        if (cur->event.id == id) {
            if (prev) prev->next = cur->next;
            else head_ = cur->next;
            if (tail_ == cur) tail_ = prev;
            Event out = cur->event;
            delete cur;
            --size_;
            reindex();
            return out;
        }
        prev = cur;
        cur = cur->next;
    }
    return std::nullopt;
}
```

**移动**采用“摘出再插入”的简单实现，避免维护两套指针逻辑：

```cpp
bool EventList::move_to(const std::string& id, int pos) {
    Event* found = find(id);
    if (!found) return false;
    Event copy = *found;
    remove(id);
    insert_at(pos, copy);
    return true;
}
```

`append` 只在尾部插入，O(1)；`find`/`at`/`index_of` 都是顺序查找 O(n)。对于记事本规模（几十到几千条）足够快，而且链表本身就是课程要求的数据结构。

### 1.3 Repository：业务层

`Repository` 把“链表操作”包装成有校验、有撤销、有持久化的业务接口。它持有 `Store` 和 `EventList`：

```cpp
class Repository {
public:
    Store store;
    EventList events;
    std::vector<std::string> warnings;

    Event& add(...);
    Event& update(...);
    Event& set_done(const std::string& id, bool done);
    bool remove(const std::string& id);
    bool move_to(const std::string& id, int pos);
    std::vector<Event*> due_on(std::time_t day);
    std::vector<Event*> search(const std::string& keyword);
    Stats stats(...) const;
    bool undo();
    bool redo();
    SyncReport sync_merge(...);
    int apply_tombstones(...);
private:
    std::vector<std::vector<json>> undo_;
    std::vector<std::vector<json>> redo_;
    static constexpr size_t kMaxUndo = 60;
};
```

#### 1.3.1 写操作统一套路

每个写操作都遵循同一顺序：

```text
require(id) / 校验标题
  → push_undo()       // 保存修改前快照，清空 redo
  → 修改内存对象
  → updated_at = now
  → save()            // 原子写盘
```

以 `update` 为例：

```cpp
Event& Repository::update(const std::string& id, ...) {
    Event& e = require(id);
    std::string clean = trim(title);
    if (clean.empty()) throw RepoError("标题不能为空");
    push_undo();
    e.title = clean;
    e.note = note;
    e.due = due;
    e.tags = tags;
    e.remind_before = std::max(0, remind_before);
    ...
    e.updated_at = now_time();
    e.last_reminded_at.reset();   // 时间改了，允许重新提醒
    save();
    return e;
}
```

`push_undo` 保存的是整个事件数组的 JSON 快照，而不是操作日志。这样做实现简单、天然支持任意复杂操作，但每个快照是 O(n) 空间；用 `kMaxUndo = 60` 控制上限。

```cpp
void Repository::push_undo() {
    undo_.push_back(snapshot());
    if (undo_.size() > kMaxUndo) undo_.erase(undo_.begin());
    redo_.clear();
}
```

`undo`/`redo` 就是两个栈互推：

```cpp
bool Repository::undo() {
    if (undo_.empty()) return false;
    redo_.push_back(snapshot());
    auto snap = undo_.back();
    undo_.pop_back();
    restore(snap);
    save();
    return true;
}
```

#### 1.3.2 查询算法

- **今日**：`Event::is_due_on(day)` 比较 `date_str(due) == date_str(day)`，只比较年月日；
- **逾期**：`!done && due < now`；
- **待办/完成**：遍历时按 `done` 分流；
- **标签统计**：只统计未完成事件，返回 `map<tag,count>`；
- **完成率**：`(done * 100.0 / total + 0.5)` 四舍五入。

搜索是“多关键字 AND”：

```cpp
std::vector<Event*> Repository::search(const std::string& keyword) {
    std::string key = lower_ascii(trim(keyword));
    // 按空格切成 terms
    for (Event* e : events.views()) {
        std::string hay = lower_ascii(e->title + " " + e->note + " " + join(e->tags, " "));
        for (const auto& a : e->attachments) hay += " " + lower_ascii(a.name);
        bool all = true;
        for (const auto& term : terms) {
            if (hay.find(term) == std::string::npos) { all = false; break; }
        }
        if (all) out.push_back(e);
    }
    return out;
}
```

`lower_ascii` 只处理 ASCII 大小写，不破坏 UTF-8 中文；因此中文按原样匹配，英文不区分大小写。附件文件名也进入搜索范围，用户可以用“封面”搜到 `cover.bmp`。

#### 1.3.3 提醒算法

`Event::needs_reminder(at)` 是提醒判定的唯一入口：

```cpp
bool Event::needs_reminder(std::time_t at) const {
    if (done || !due.has_value()) return false;
    auto moment = remind_at();                 // due - remind_before * 60
    if (!moment.has_value()) return false;
    if (snooze_until.has_value() && *snooze_until > *moment)
        moment = snooze_until;                 // “5 分钟后再提醒”
    if (at < *moment) return false;
    if (last_reminded_at.has_value() && *last_reminded_at >= *moment)
        return false;                          // 这一轮已经响过
    return true;
}
```

这个设计解决了三个边界：

1. 提前提醒：`moment = due - N 分钟`；
2. 贪睡：`snooze_until` 把下一次提醒推后；
3. 重复提醒：`last_reminded_at` 记录已响时刻，避免 30 秒轮询重复弹窗。

`Repository::next_reminder_at(after)` 则用于计算“下一次该在什么时候醒”，把已经过点但未响的事件立即返回 `after`。

### 1.4 Store：持久化与容错

`Store` 负责目录布局、读写、备份、附件和路径安全。

#### 1.4.1 原子写

所有文件写入都走 `write_bytes_atomic`：

```cpp
bool write_bytes_atomic(const fs::path& path, const Bytes& data) {
    fs::path tmp = path;
    tmp += ".tmp-" + random_hex(4);
    { std::ofstream out(tmp, std::ios::binary | std::ios::trunc);
      out.write(...); out.flush(); }
#ifdef _WIN32
    return MoveFileExW(tmp.wstring().c_str(), path.wstring().c_str(),
                       MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH);
#else
    fs::rename(tmp, path, ec);
#endif
}
```

`MOVEFILE_WRITE_THROUGH` 让替换操作尽量落盘；即使进程在写入中途崩溃，原文件仍然完整，临时文件最多是垃圾。

#### 1.4.2 损坏恢复

`Store::load_events` 先读 `events.json`，失败后读 `events.json.bak`，并把损坏文件改名为 `events.json.corrupt-<时间戳>` 隔离：

```cpp
if (auto events = try_load(events_path, false)) return *events;
if (auto events = try_load(backup_path, true)) return *events;
return {};
```

`try_load` 内部只接受“顶层对象且包含 events 数组”或“顶层数组”；单条坏记录在 `Repository::reload` 中被跳过并写入 `warnings`，不会让整个文件打不开。

#### 1.4.3 备份策略

每次成功保存会：

1. 写 `events.json`；
2. 写 `events.json.bak`；
3. 写 `backups/events-YYYYMMDD-HHMMSS-微秒.json`；
4. 只保留最近 `keep_backups`（默认 20）份。

微秒后缀避免同一秒内多次保存互相覆盖。

#### 1.4.4 附件路径安全

附件在磁盘上是 `attachments/<event-id>/<文件名>`，JSON 里存相对路径。读取时 `Store::resolve` 用 `weakly_canonical` 展开 `..`，再检查结果是否仍在数据目录下：

```cpp
fs::path full = fs::weakly_canonical(dir / rel_path, ec);
fs::path base = fs::weakly_canonical(dir, ec);
if (full_str.size() < base_str.size() ||
    full_str.compare(0, base_str.size(), base_str) != 0) {
    throw StoreError("附件路径越界：" + rel);
}
```

这可以阻止恶意 `.mjnote` 里写 `../../Windows/...` 覆盖系统文件。文件名本身也会过滤 `<>:"/\|?*` 和控制字符，并处理重名（`a.png`、`a-1.png`）。

### 1.5 时间处理

`src/core/util.cpp` 自己实现了宽松的时间解析，支持：

- `2026-11-29 18:00`
- `2026/11/29 18:00`
- `2026-11-29T18:00:00`
- `11-29`（补当前年份）
- `18:00`（补今天）
- 结尾 `Z`（忽略时区后缀）

`humanize_due` 把时间转成人话：

```text
已逾期 3 分钟 / 已逾期 2 小时 / 已逾期 1 天
23 分钟后 / 今天 18:00 / 明天 09:00 / 周三 19:30 / 2026-12-05 09:00
```

这套显示逻辑 PC、TUI、Android 三端保持一致，避免同一任务在不同端显示不同文案。

### 1.6 Markdown 渲染算法

`src/gui/markdown.cpp` 是一个“够用”的块级 + 行内解析器，不引入第三方 Markdown 库。

块级解析顺序：

```text
``` 代码块 ``` → 表格（当前行有 | 且下一行是分隔行）
→ # 标题 → ---/***/___ 分隔线 → > 引用
→ -/*/+ 无序列表（含 [x]/[ ] 任务）
→ 1. 有序列表 → 普通段落
```

行内替换顺序很关键：

```cpp
text.replace("&", "&amp;"); ...          // 先转义 HTML
text.replace("`([^`]+)`", "<code>\\1</code>");  // 行内代码先占位
text.replace("\\*\\*(.+?)\\*\\*", "<b>\\1</b>");
text.replace("__(.+?)__", "<b>\\1</b>");
text.replace("~~(.+?)~~", "<s>\\1</s>");
text.replace("\\+\\+(.+?)\\+\\+", "<u>\\1</u>");
text.replace("==(.+?)==", "<span style=\"background:#fff3b0;color:#1c2130\">\\1</span>");
text.replace("\\{color:(#[0-9a-fA-F]{3,8}|[a-zA-Z]+)\\}(.+?)\\{/color\\}", ...);
text.replace("\\*(?!\\*)(.+?)(?<!\\*)\\*", "<i>\\1</i>");
```

顺序原因：先转义防止 XSS；行内代码先处理，避免代码里的 `**` 被当成粗体；最后才处理单星号斜体，并用负向断言避免吃掉 `**`。

表格识别用一个正则判断分隔行：

```cpp
static const QRegularExpression re(
    "^\\s*\\|?\\s*:?-{2,}:?\\s*(\\|\\s*:?-{2,}:?\\s*)*\\|?\\s*$");
```

渲染结果为完整 HTML，并注入浅色/深色两套 CSS 变量；`QTextBrowser` 直接显示。这样预览和页面里的文字层共用同一套颜色规则。

### 1.7 页面与墨迹数据

页面不是一张截图，而是一个 JSON 图层描述，保存在 `Event.page_layout`：

```json
{
  "text":  {"x": 40, "y": 40, "z": 10, "w": 680},
  "images": [
    {"path": "attachments/<id>/a.png", "x": 60, "y": 200,
     "w": 240, "h": 160, "rot": 0, "z": 20}
  ],
  "hidden": ["attachments/<id>/old.png"],
  "ink": [
    {"color": "#1f2430", "width": 4,
     "points": [[120,300],[124,305],[130,312]]}
  ]
}
```

- `text` 是 Markdown 文字层，可移动、可调层级；
- `images` 是附件图片的变换（位置、宽高、旋转、z）；
- `ink` 是自由笔迹：颜色、线宽、点序列；
- `hidden` 记录“从页面移除但保留附件”的图片。

墨迹与图片用 z 值决定叠放顺序；页面编辑器的“置顶/置底”实际就是修改 z 值，因此可以真正压过墨迹层。保存时序列化为 JSON 写回事件，随 `events.json` 和 `.mjnote` 一起同步。

### 1.8 导入导出与 .mjnote

`src/core/importer.cpp` 支持四种格式：

| 格式 | 方向 | 说明 |
| --- | --- | --- |
| `.json` | 双向 | 与 `events.json` 同构，适合备份 |
| `todo.txt` | 双向 | `(A)` 优先级、`due:`、`+tag`、`x` 完成 |
| `.md` | 只导出 | 每条任务一个标题 + 元信息 + 备注 |
| `.mjnote` | 双向 | store ZIP，含附件，跨设备迁移 |

`.mjnote` 的结构：

```text
manifest.json
files/<event-id>/0_cover.png
files/<event-id>/1_note.txt
```

`zip.cpp` 是手写的 ZIP 读写器：

- 写：只使用 method 0（store），计算 CRC32，写本地文件头、中央目录、EOCD；
- 读：从文件尾向前找 EOCD，遍历中央目录，按本地头偏移取数据；
- 文件名使用 UTF-8 标志位 `0x0800`，中文附件名不会乱码。

导入 `.mjnote` 时，附件先写入当前数据目录的 `attachments/<new-id>/`，再把 JSON 中的相对路径重映射到新文件；因此同一个包可以在不同设备、不同数据目录重复导入。

### 1.9 云同步合并算法（PC 侧）

`Repository::sync_merge` 是纯内存算法，输入远端事件数组，输出合并后的本地事件数组：

```cpp
struct SyncReport {
    int added;       // 远端新增
    int pulled;      // 采用远端（新增 + 覆盖）
    int kept_local;  // 本地较新
    int skipped;     // 指纹重复
    int local_only;  // 仅本地有
};
```

核心规则：

1. **同 id**：比较 `updated_at`（缺失时回退 `created_at`），远端更大才覆盖；
2. **不同 id 但标题 + `created_at` 相同**：视为同一条，跳过，避免导入两次；
3. **本地独有**：保留，并计入 `local_only`，上传时会带到云端；
4. 合并后按 priority 稳定排序并重新编号，保持链表不变量；
5. 覆盖前调用 `fill_attachments` 把远端附件落盘并重映射路径。

墓碑删除由 `apply_tombstones` 完成：

```cpp
for (const Event& e : events.all_copy()) {
    auto it = tombstones.find(e.id);
    if (it != tombstones.end()) {
        std::time_t stamp = e.updated_at.value_or(e.created_at.value_or(0));
        if (stamp <= it->second) { removed++; continue; }  // 云端删除更新
    }
    kept.push_back(e);
}
```

如果本地在云端删除之后又修改过（`stamp > 删除时间`），则保留本地记录，避免“刚改完就被旧墓碑删掉”。

## 2. PC 端 GUI 与 TUI

PC 端有三套界面：Qt GUI、控制台 TUI、命令行 CLI。三者共享 `Repository`，因此“在 GUI 里改一条，TUI 里立刻能看到”不是靠同步代码，而是靠同一个文件。

### 2.1 Qt GUI 总体结构

`src/gui/qt_gui.cpp` 的主体是 `MainWindow`（约 5000 行）。它没有使用 Designer 的 `.ui` 文件，而是全部用代码搭布局，便于在代码里直接绑定自定义控件和主题。

窗口由三栏组成：

```text
QSplitter
├─ 左栏 build_sidebar()      固定 300px，统计卡/视图/标签/主题/云同步
├─ 中栏 build_center()       搜索 + 卡片列表
└─ 右栏 build_editor_stack() QStackedWidget
   ├─ build_view_page()      只读详情 + 页面 + 附件
   └─ build_editor()         编辑表单 + 备注四标签页
```

`build_editor_stack()` 里有一个重要处理：把编辑页包进 `QScrollArea`，并让它“横向可压缩、纵向可滚动”：

```cpp
auto* edit_page = build_editor();
edit_page->setSizePolicy(QSizePolicy::Ignored, QSizePolicy::Preferred);
auto* edit_scroll = new QScrollArea(editor_stack_);
edit_scroll->setWidgetResizable(true);
edit_scroll->setFrameShape(QFrame::NoFrame);
edit_scroll->setHorizontalScrollBarPolicy(Qt::ScrollBarAlwaysOff);
edit_scroll->setWidget(edit_page);
```

原因：右栏宽度有限，而编辑页的“截止/提醒/铃声/优先级/工具栏”等行有最小宽度。如果 `QScrollArea` 按 `minimumSizeHint` 给宽度，内容会被横向裁掉；把横向策略设为 `Ignored` 后，窗口窄时布局会主动压缩控件，只有高度不足时才出现纵向滚动条。

### 2.2 卡片列表与筛选

`refresh_list()` 先销毁旧卡片，再按 `visible_events()` 重建：

```cpp
std::vector<Event*> visible_events() {
    std::vector<Event*> base;
    if (mode_ == "today") base = repo_.due_on(now_time());
    else if (mode_ == "pending") base = repo_.pending();
    else if (mode_ == "done") base = repo_.finished();
    else if (mode_ == "overdue") base = repo_.overdue();
    else base = repo_.all();
    // 标签过滤 + 关键字过滤
    return out;
}
```

每次刷新同时更新四张统计卡、五个导航按钮的计数、标签云、搜索结果的“共 N 条”。卡片 `EventCard` 自己负责绘制左侧色条、图标、优先级、截止时间、标签、附件数，并暴露三个回调：

```cpp
new EventCard(event, pal,
    [this, id](Qt::KeyboardModifiers mods) { select_event(id, mods); }, // 选中
    [this, id] { toggle_event(id); },                                   // 勾选完成
    [this, id] { ... load_editor(e); ... },                             // 进入编辑
    cards_container_);
```

这样卡片不需要知道 `MainWindow` 的内部状态，只发事件。

### 2.3 多选：Ctrl / Shift / Ctrl+Shift

`select_event(id, mods)` 维护三个状态：

- `selection_`：当前选中的 id 集合；
- `anchor_id_`：范围选择的锚点；
- `current_id_`：右侧详情当前显示的那一条。

```cpp
if ((mods & Qt::ShiftModifier) && !anchor_id_.isEmpty()) {
    // 找到 anchor 和当前 id 在可见列表中的下标 a、b
    // 不带 Ctrl 时先 clear，再把 [min(a,b), max(a,b)] 全部加入
} else if (mods & Qt::ControlModifier) {
    // 切换单条选中；如果取消后为空，则保留当前条
} else {
    selection_.clear();
    selection_.insert(qid);
    anchor_id_ = qid;
}
```

`Ctrl+Shift` 是“保留已有选择，再追加一段范围”，所以判断顺序是 `Shift` 优先，在 Shift 分支里再看 `Control` 决定是否清空。多选时右侧详情不展开，避免每点一条就刷新页面；只有普通单击才 `load_view()`。

选中的卡片通过 `apply_card_selection()` 统一更新边框和背景；选中数大于 1 时显示“完成选中 / 删除选中”两个批量按钮。

### 2.4 编辑、自动保存与取消

编辑页的所有输入控件都连接 `schedule_save()`：

```cpp
void schedule_save() {
    if (loading_) return;       // 正在从模型灌数据，不能反向保存
    save_timer_->start();       // 650ms 单次定时器
}
```

`save_current()` 从控件收集字段，做标题非空校验，调用 `repo_.update(...)`，然后刷新卡片和元信息。`loading_` 标志用于防止“加载事件 → 触发 textChanged → 又保存”的回环。

取消编辑不是简单地“不保存”，因为自动保存可能已经把内容写盘了。`load_event(edit=true)` 在进入编辑前保存一份完整 `Event` 快照：

```cpp
if (edit && !editing_ && e && !edit_is_new_) {
    edit_snapshot_ = *e;
    edit_snapshot_valid_ = true;
}
```

`cancel_edit_changes()` 把快照重新写回：

```cpp
repo_.update(id, snap.title, snap.note, snap.due, snap.tags,
             snap.remind_before, snap.color, snap.icon,
             snap.page_layout, snap.system_notify);
repo_.set_ringtone(id, snap.ringtone);
repo_.set_snooze(id, snap.snooze_until);
repo_.set_done(id, snap.done);
if (snap.priority != old_priority) repo_.move_to(id, snap.priority);
```

新建事项取消则直接删除刚创建的记录。这样“取消”在视觉上就是回到进入编辑前，而不是“停止后续自动保存”。

### 2.5 附件：从底部面板到独立标签页

1.2.0 之前附件面板固定占编辑页底部 170px，导致备注区被压得很短。现在附件是 `note_tabs_` 的第四个标签：

```cpp
att_panel_ = new QWidget(note_tabs_);
auto* att_panel_layout = new QVBoxLayout(att_panel_);
att_panel_layout->setContentsMargins(10, 8, 10, 8);
att_panel_layout->addWidget(att_list_, 1);
note_tabs_->addTab(att_panel_, "附件");
```

附件列表 `AttachmentList` 支持拖入文件、拖动排序、右键移除、双击打开。拖放事件把路径交给 `MainWindow::attach_files()`，后者调用 `Repository::add_attachment()`，由 `Store` 复制到 `attachments/<id>/` 并返回相对路径。

### 2.6 备注四标签页

`note_tabs_` 包含：

1. **编辑**：`NoteEdit`（继承 `QTextEdit`），支持粘贴图片、拖入文件；
2. **预览**：`QTextBrowser`，显示 `markdown_to_html()` 的结果；
3. **页面**：`PageEditor`，OneNote 风格图层；
4. **附件**：上面的附件列表。

切换标签时：

```cpp
connect(note_tabs_, &QTabWidget::currentChanged, this, [this](int index) {
    if (index == 1) update_preview();
    if (index == 2) {
        if (Event* e = current()) page_->set_event(e);
    }
});
```

预览不是实时逐字刷新，而是由 180ms 的 `markdown_timer_` 合并输入事件，避免每按一个键就重新解析整篇 HTML。页面则同时接收 `set_note()`，让文字层跟着备注更新。

### 2.7 页面编辑器：QGraphicsScene 的三层结构

`src/gui/page_view.cpp` 用 `QGraphicsScene` 实现页面。场景宽固定 820，坐标单位与 PC/Android 的 `page_layout` 完全一致。

场景中的图元：

```text
PageTextItem      z=10     Markdown 文字层（QGraphicsTextItem）
PageImageItem     z=20+    图片层，可拖动/缩放/旋转
InkLayer          z=1000   墨迹层，自绘 QGraphicsItem
```

`PageTextItem` 不是纯文本，它内部用 `QTextDocument` 渲染 Markdown 的 HTML；`PageImageItem` 保存 `path/x/y/w/h/rot/z`，鼠标事件负责三种模式：

```text
Mode::Move    拖动图片
Mode::Resize  右下角手柄缩放
Mode::Rotate  顶部圆点旋转
```

`InkLayer` 保存 `std::vector<InkStroke>`，每一笔是颜色、线宽、点序列。鼠标按下开始一笔，移动追加点，松开结束；橡皮擦按距离删除整笔（不是擦除像素），因此撤销/清空都很简单：

```cpp
struct InkStroke {
    QColor color;
    qreal width;
    QVector<QPointF> points;
};
```

### 2.8 页面缩放、适宽与整页

`PageView` 继承 `QGraphicsView`，实现三种滚轮行为：

```text
滚轮              → 上下滚动
Ctrl + 滚轮       → 左右滚动
Ctrl+Shift + 滚轮 → 以鼠标为锚点缩放
```

1.2.0 新增了“适宽/整页”两种自动适配模式：

```cpp
enum class FitMode { None, Width, Page };

void apply_fit() {
    if (fit_mode_ == FitMode::Page) {
        setHorizontalScrollBarPolicy(Qt::ScrollBarAlwaysOff);
        setVerticalScrollBarPolicy(Qt::ScrollBarAlwaysOff);
        fitInView(sceneRect.adjusted(-24,-24,24,24), Qt::KeepAspectRatio);
    } else {
        setHorizontalScrollBarPolicy(Qt::ScrollBarAsNeeded);
        setVerticalScrollBarPolicy(Qt::ScrollBarAsNeeded);
        const qreal factor = viewport()->width() / (sceneRect.width() + 32.0);
        resetTransform();
        scale(factor, factor);
    }
    zoom_ = transform().m11();
}
```

- 默认 `Width`：页面宽度刚好铺满视口，纵向可滚动，适合编辑；
- `Page`：整页缩放到视口内，适合总览；
- 用户一旦 `Ctrl+Shift+滚轮` 手动缩放，`fit_mode_` 变为 `None`，并恢复滚动条，否则从“整页”模式退出后无法平移。

`resizeEvent` 和 `showEvent` 都会调用 `refit_if_auto()`，所以拖动窗口、切换分屏时页面始终贴合。`fitting_` 布尔量防止“设置滚动条 → 触发 resize → 再次 fit”的递归。

### 2.9 页面保存与独立窗口

页面每次变化（墨迹、图片移动、文字层移动）都会 `schedule_save()`，700ms 后把 `page_layout` JSON 写回事件：

```cpp
root.put("text",  {{"x",...},{"y",...},{"z",...},{"w",...}});
root.put("images", imagesJson);
root.put("hidden", hiddenJson);
root.put("ink", inkJson);
repo_.set_visual(current_id, std::nullopt, std::nullopt, root.dump());
```

`DetachedPageWindow` 是一个独立的 `QMainWindow`，内部复用 `PageEditor`。拖出后编辑也在这个窗口里进行，不再占用主窗口右栏。它和主窗口共享同一个 `Repository`，保存后通过 `on_saved` 回调刷新主窗口列表。

### 2.10 主题、QSS 与品牌

主题不是简单的 `setStyleSheet` 全量替换，而是先构造 `Pal` 调色板：

```cpp
struct Pal {
    QColor bg, panel, card, text, muted, border;
    QColor primary, primarySoft, success, warning, error;
};
```

`apply_theme(name, save)` 根据浅色/深色生成调色板，然后：

1. 生成 QSS（`QFrame#Sidebar`、`QPushButton#Primary`、`QFrame#EventCard` 等对象名选择器）；
2. 通知 `PageEditor::set_dark()` 切换页面纸张反相；
3. 更新 `Toast`、`StatCard`、`EventCard` 的颜色；
4. 保存到 `config.json`。

品牌区（应用名、副标题、Logo）也走同一套配置：`brand_icon` 可以是图片路径，`brand_emoji` 是文字 Logo；`LogoEditorDialog` 支持裁剪、缩放、平移，并保持 GIF 动画。窗口图标在启动时通过 `QApplication::setWindowIcon(QIcon(":/assets/app.png"))` 设置，EXE 图标由 `src/app.rc` + `windres` 嵌入。

### 2.11 云同步界面

`CloudClient` 继承 `QObject`，用 `QNetworkAccessManager` 发请求，全部异步，通过信号回主线程：

```text
authOk / authFailed
metaReady / metaFailed
bundleReady / bundleFailed
uploadOk / uploadConflict / uploadFailed
```

`MainWindow` 只处理信号：登录成功保存 token；`metaReady` 计算差异；大变化弹窗；`bundleReady` 调用 `Repository::sync_merge()`；`uploadConflict` 重新拉 meta 再重试。界面层不直接拼 HTTP。

### 2.12 TUI 总体结构

TUI 在 `src/tui/tui.cpp`，只在 Windows 下启用。它没有用 ncurses，而是直接调用 Win32 Console API：

- `Console::init()`：保存原模式，开启 `ENABLE_VIRTUAL_TERMINAL_PROCESSING`，进入备用屏幕；
- `Console::read_key()`：用 `ReadConsoleInputW` 同时读键盘、鼠标、窗口大小变化；
- 输出用 ANSI 真彩色 + 光标定位，`draw()` 每帧重绘。

主循环：

```cpp
for (;;) {
    draw();
    Key key = console_.read_key(900);   // 900ms 超时，用于提醒轮询
    if (key.type == Key::Type::None) { tick(); continue; }
    if (handle(key)) break;
}
```

`tick()` 做两件事：

1. `repo_.due_reminders(now)`，有到期任务就响铃/播放铃声，并 `mark_reminded`；
2. 比较 `events.json` 的 `mtime`，发现被其他进程修改就 `repo_.reload()`。

这让 TUI 和 GUI 可以同时打开：在 GUI 里改一条，TUI 最多 900ms 后自动刷新。

### 2.13 TUI 三栏布局与绘制

`draw()` 先计算终端宽高：

```text
左侧栏 sidebar_width（默认 44）
中栏 = 剩余宽度 × 约 45%
右栏 = 剩余宽度
```

然后分别绘制：

- 左栏：品牌、今日/逾期/待办/完成率、搜索框、视图计数、任务列表、底部快捷键；
- 中栏：选中任务的详情，包含标题、元信息、Markdown 备注、附件；
- 右栏：帮助/提示/滚动条。

终端里没有“像素”，所以所有对齐都用 `display_width()` 计算显示宽度：中文和全角符号算 2 列，ANSI 转义序列算 0 列。`pad_display()`、`truncate_display()`、`wrap_display()` 都基于这个函数，避免中英文混排时边框错位。

### 2.14 TUI 的 Markdown 与表格

TUI 不能显示 HTML，所以它实现了一个“终端版”行内样式解析器：

```cpp
struct InlineStyle {
    bool bold, italic, underline, strike, has_color;
    Rgb color;
};
struct StyledGlyph {
    std::string text;   // 一个 UTF-8 字符
    InlineStyle style;
};
```

`parse_inline_styled()` 逐字符扫描 `**`、`*`、`++`、`~~`、`==`、`{color:...}`，输出带样式的 glyph 序列；`wrap_styled()` 按显示宽度换行，保证样式不丢。表格则用 `parse_table_row()` + `table_separator()` 识别，动态计算每列宽度，再用 `┌┬┐├┼┤└┴┘` 画边框。

### 2.15 TUI 的模态表单

按 `a`/`e` 打开 `show_event_form()`，它是一个居中的模态窗口，包含：

```text
标题
截止 [YYYY-MM-DD HH:MM]  提醒 [N] 分  位置 [末位]
快捷：F1 今天18:00  F2 明天09:00  F3 下周一09:00  F4 清除

```

交互：

- `Tab` / `↑` / `↓` 切换焦点；
- `Ctrl+S` 保存，`Esc` 取消；
- 备注里 `Enter` 换行，其他字段 `Enter` 跳到下一个；
- `Backspace` 按 UTF-8 字符边界删除，不会删半个汉字；
- 保存时统一校验标题、时间格式、提醒分钟数、位置范围。

### 2.16 TUI 的鼠标与帮助

`read_key()` 把鼠标事件转成 `Key::Type::Mouse`，`handle_mouse()` 根据坐标判断：

## 3. PC 端命令行指令

命令行入口是 `src/main.cpp`。Windows 下 `main` 先做两件事：

1. 用 `CommandLineToArgvW` 取宽字符参数，再转 UTF-8，避免中文标题在 GBK 代码页下乱码；
2. `SetConsoleOutputCP(65001)` + 开启 VT 处理，保证 TUI/彩色输出正常。

全局参数：

```text
moji [--data-dir DIR] [--version] [--help]
```

`--data-dir` 指定数据目录；不指定时依次看 `MOJI_HOME` 环境变量、`%USERPROFILE%\.moji`。

### 3.1 命令分发

```cpp
std::string command = i < argc ? argv[i++] : "";
if (command.empty()) {
    if (isatty(stdin) && isatty(stdout)) return run_tui(repo);
    print_help();
    return 0;
}
if (command == "tui") return run_tui(repo);
if (command == "gui") return run_gui(repo, shot);
if (command == "add") return cmd_add(...);
...
```

空命令且 stdin/stdout 都是终端 → 进入 TUI；被管道调用（例如脚本里 `moji | grep`）→ 打印帮助，避免把交互界面输出到管道。

### 3.2 add

```bat
moji add "买牛奶" -u "2026-11-24 18:00" -t 生活 -p 2 -r 30 -n "备注"
```

参数：

| 参数 | 含义 |
| --- | --- |
| `-u/--due` | 截止时间，支持多种格式 |
| `-t/--tag` | 标签，可重复，逗号/空格分隔 |
| `-p/--pos` | 插入位置，1 基；省略则追加 |
| `-r/--remind` | 提前多少分钟提醒 |
| `-n/--note` | 备注 |

实现要点：

- 位置 `> 0` 才传给 `Repository::add`，否则追加；
- 写操作前 `snapshot_before_write(repo)` 保存跨进程撤销快照；
- 输出 `已添加 Pn：标题 [截止文案]`。

## 4. Android 端核心算法

Android 端不是 PC 的“远程界面”，而是一个独立的本地优先客户端：数据存在手机私有目录，格式与 PC 完全一致，可选地通过 SAF 目录或云服务同步。

### 4.1 数据模型与时间

`data/Model.kt` 用 Kotlin `data class` 复刻 PC 的字段：

```kotlin
data class MojiEvent(
    val id: String = "",
    val title: String = "",
    val note: String = "",
    val due: Long? = null,          // Unix 秒
    val priority: Int = 1,
    val done: Boolean = false,
    val doneAt: Long? = null,
    val tags: List<String> = emptyList(),
    val attachments: List<Attachment> = emptyList(),
    val createdAt: Long? = null,
    val updatedAt: Long? = null,
    val remindBefore: Int = 0,
    val systemNotify: Boolean = false,
    val lastRemindedAt: Long? = null,
    val color: String = "",
    val icon: String = "",
    val pageLayout: String = "",
    val ringtone: String = "",
    val snoozeUntil: Long? = null,
)
```

`MojiTime` 负责时间：

- `iso(seconds)` / `parse(raw)` 与 PC 的 `iso_from_time` / `parse_datetime` 对齐；
- `startOfDay`、`sameDay` 用 `Calendar` 按本地时区计算；
- `humanize(due, now)` 生成与 PC 相同的“已逾期 1 小时 / 明天 09:00”。

`fingerprint()` 是同步去重键：

```kotlin
fun fingerprint(): String = "$title\u001f${createdAt ?: 0L}"
```

用 `\u001f`（单元分隔符）而不是普通空格，避免标题里带空格时产生歧义。

### 4.2 Repository：本地仓储

`data/Repository.kt` 的目录布局与 PC 一致：

```text
filesDir/moji/
├─ events.json
├─ events.json.bak
├─ backups/events-*.json
├─ config.json
├─ attachments/<event-id>/
├─ ringtones/
└─ brand/
```

所有读写都在 `synchronized(lock)` 内完成，避免 Compose 主线程与 IO 协程同时改列表。

#### 4.2.1 重新编号

Android 用不可变 `List` 而不是链表，但保持同样的不变量：

```kotlin
fun reindexed(events: List<MojiEvent>): List<MojiEvent> =
    events.sortedWith(compareBy({ it.priority }, { it.createdAt ?: 0L }))
        .mapIndexed { index, event -> event.copy(priority = index + 1) }
```

插入、删除、移动后都调用它。这样 UI 永远可以按 `priority` 排序，不需要额外的链表指针。

#### 4.2.2 写操作与撤销

每个写操作先 `pushUndo()` 保存当前列表，再生成新列表并 `persist()`：

```kotlin
val list = events.toMutableList()
val index = if (position == null) list.size else (position - 1).coerceIn(0, list.size)
list.add(index, event)
events = reindexed(list)
persist(events)
```

`pushUndo()` 把 `events` 整体压入 `ArrayDeque`，`undo()`/`redo()` 互推。与 PC 的内存快照策略一致。

`update()` 里有一个容易漏掉的细节：

```kotlin
snoozeUntil = if (event.due == events[index].due) event.snoozeUntil else null,
lastRemindedAt = if (event.due == events[index].due) event.lastRemindedAt else null,
```

用户改了截止时间后，旧的“稍后提醒”和“已提醒”必须失效，否则新时间不会响。

#### 4.2.3 附件

`saveAttachmentBytes(eventId, name, bytes, mime)`：

1. 创建 `attachments/<eventId>/`；
2. 过滤非法字符、处理重名（`a-1.png`）；
3. 写入文件；
4. 返回相对路径、MIME、大小、添加时间。

读取时 `resolve(relativePath)` 把相对路径拼到 `dataDir` 下，并检查 `canonicalPath` 仍以数据目录开头，防止 `../` 越界。

### 4.3 Merge：导入与双向同步

`data/Merge.kt` 是纯函数，方便单元测试。

#### 4.3.1 importEvents

导入规则与 PC `Repository::import_events` 对齐：

```text
merge=false：清空本地，全部导入
merge=true ：id 已存在或指纹已存在 → 跳过
             id 冲突但内容不同 → 生成新 id
             标题为空 → 跳过
```

#### 4.3.2 syncMerge

```kotlin
fun syncMerge(local: List<MojiEvent>, remote: List<MojiEvent>): SyncResult {
    val merged = LinkedHashMap<String, MojiEvent>()
    val fingerprints = HashSet<String>()
    local.forEach { merged[it.id] = it; fingerprints.add(it.fingerprint()) }
    var pulled = 0
    var keptLocal = 0
    for (remoteEvent in remote) {
        val current = merged[remoteEvent.id]
        if (current != null) {
            val localTime = current.updatedAt ?: current.createdAt ?: 0L
            val remoteTime = remoteEvent.updatedAt ?: remoteEvent.createdAt ?: 0L
            if (remoteTime > localTime) {
                merged[remoteEvent.id] = remoteEvent
                pulled++
            } else {
                keptLocal++
            }
            continue
        }
        if (remoteEvent.fingerprint() in fingerprints) continue
        merged[remoteEvent.id] = remoteEvent
        fingerprints.add(remoteEvent.fingerprint())
        pulled++
    }
    return SyncResult(reindexed(merged.values.toList()), pulled, keptLocal)
}
```

与 PC 的差异：Android 的 `pulled` 同时统计“新增”和“覆盖”，UI 再用列表长度差算出 `added`。

### 4.4 .mjnote 编解码

`data/MjnoteCodec.kt` 与 PC `zip.cpp` 完全兼容：

- manifest 为 `{"app":"moji-note","version":2,"events":[...]}`；
- 附件路径 `files/<event-id>/<index>_<name>`；
- 写出时用 `STORED`（method 0），因为 PC 的读实现只支持 store；
- 读取时兼容 deflate（`ZipInputStream` 默认支持）。

编码：

```kotlin
val member = "files/${event.id}/${index}_${safeZipName(attachment.name)}"
entries.add(member to data)
aj.put("src", member)
```

解码时把附件字节放进 `payloads["eventId#index"]`，由 `Repository.mergeCloudBundle` / `importBundle` 落盘并重映射路径。这样 Codec 不依赖文件系统，便于测试。

### 4.5 SAF 目录同步

`data/SyncManager.kt` 支持“把 PC 数据目录（或另一台手机）当作同步盘”：

- `readRemoteEvents(uri)`：通过 `DocumentFile` 读取 `events.json`；
- `pull(uri, merge)`：读远端 → `Merger.syncMerge` → 复制缺失附件 → `replaceAll`；
- `push(uri)`：先把旧 `events.json` 备份为 `events.json.bak`，再写新文件；附件按相对路径逐级查找/创建目录；
- `twoWay(uri)`：先 pull 再 push。

`findRemote()` 把 `attachments/<id>/a.png` 拆成路径段，逐段 `findFile`，不存在时按需 `createDirectory` / `createFile`。这是 SAF 没有“mkdir -p”时的通用做法。

### 4.6 提醒：AlarmManager + WorkManager

Android 的提醒不能靠一个常驻进程，因此用两层：

1. **精确闹钟**：`ReminderScheduler.scheduleAll()` 为每个未完成、未过期的任务调用 `AlarmManager.setExactAndAllowWhileIdle(RTC_WAKEUP, moment, pendingIntent)`；Android 12+ 没有精确闹钟权限时降级为 `setAndAllowWhileIdle`。
2. **周期扫描**：`WorkManager` 每 15 分钟跑一次 `ReminderWorker`，兜底补发漏掉的提醒（例如设备重启、权限被撤销）。

`PendingIntent` 的 requestCode 用 `eventId.hashCode()`，保证每个事件一个独立闹钟；`SharedPreferences` 记录上次安排的 id 集合，下次安排时取消已删除/已完成事件的旧闹钟。

`ReminderReceiver` 收到广播后：

- 创建通知渠道（普通 + 闹钟高优先级）；
- 启动 `AlarmActivity` 全屏页；
- `AlarmPlayer` 循环播放铃声，支持静音、5 分钟后再提醒、完成。

### 4.7 云同步合并（Android 侧）

`Repository.mergeCloudBundle(bytes)`：

```kotlin
val decoded = MjnoteCodec.decode(bytes)
val localById = events.associateBy { it.id }
val prepared = decoded.events.map { remote ->
    val current = localById[remote.id]
    val remoteTime = remote.updatedAt ?: remote.createdAt ?: 0L
    val localTime = current?.let { it.updatedAt ?: it.createdAt ?: 0L }
    val wins = when {
        current != null -> remoteTime > localTime!!
        remote.fingerprint() in localFps -> false
        else -> true
    }
    if (!wins) remote.copy(attachments = emptyList())
    else { /* 把 decoded.payloads 中的附件写入本地并重映射 */ }
}
val result = Merger.syncMerge(local, prepared)
```

注意“输的那一方”会把附件列表清空，避免把远端附件重复落盘；只有真正采用远端版本时才写附件。

`applyCloudTombstones(tombstones)` 与 PC 相同：本地 `updatedAt <= 删除时间` 才删除；本地更新过则保留。

### 4.8 ViewModel：状态与云同步编排

`ui/MojiViewModel.kt` 是 UI 与数据层之间的唯一桥梁。它暴露 `StateFlow`：

```kotlin
val events: StateFlow<List<MojiEvent>>
val visibleEvents: StateFlow<List<MojiEvent>>   // 过滤 + 搜索 + 标签
val stats: StateFlow<LibraryStats>
val settings: StateFlow<UiSettings>
val cloudPrompt: StateFlow<CloudPrompt?>
val messages: SharedFlow<String>
```

`visibleEvents` 用 `combine(events, filter, query, selectedTag)` 计算，UI 只 collect，不自己过滤。

云同步流程：

1. `cloudCheck(manual, startup)` → `CloudApi.meta()`；
2. `cloudDiff()` 统计远端新增/更新/删除、本地新增/更新、附件差；
3. 变化大（`max(4, 本地数×25%)` 或附件差 ≥ 5）→ 设置 `cloudPrompt`，弹窗；
4. `performCloudSync()`：
   - 下载 `.mjnote`；
   - `mergeCloudBundle`；
   - `applyCloudTombstones`；
   - 导出本地 bundle；
   - `CloudApi.upload(baseVersion, deletedIds)`；
   - 409 时重新拉 meta，最多重试 2 次；
5. 成功后记录 `cloudLastVersion`、`cloudLastSync`、`cloudLastIds`。

`cloudLastIds` 用于计算“上次同步后本地删除了哪些 id”，上传时放进 `X-Moji-Deleted`，服务端据此写墓碑。

## 5. Android 端 UI 设计

Android 端使用 Kotlin + Jetpack Compose + Material 3，没有 XML 布局。整体是“单 Activity + 状态驱动的页面切换”。

### 5.1 根状态机

`MainActivity.kt` 用几个 `rememberSaveable` 状态决定显示哪个页面：

```kotlin
var tab by rememberSaveable { mutableStateOf("home") }        // 任务/搜索/设置
var detailId by rememberSaveable { mutableStateOf<String?>(null) }
var editorOpen by rememberSaveable { mutableStateOf(false) }
var editorId by rememberSaveable { mutableStateOf<String?>(null) }
var cloudOpen by rememberSaveable { mutableStateOf(false) }
```

渲染优先级：

```kotlin
when {
    cloudOpen -> CloudScreen(...)
    editorOpen -> EditorScreen(...)
    detailId != null -> DetailScreen(...)
    else -> Scaffold(bottomBar = 底部导航, fab = 新建) { ... }
}
```

这样做的好处：

- 没有 Navigation 库的额外依赖；
- 旋转屏幕后 `rememberSaveable` 恢复页面；
- 详情/编辑/云登录是全屏页，不会被底部导航挡住。

全屏页不在 `Scaffold` 内，默认拿不到 `LocalContentColor`。1.2.0 在根节点补了：

```kotlin
CompositionLocalProvider(LocalContentColor provides MaterialTheme.colorScheme.onBackground) {
    Box(Modifier.fillMaxSize().background(MaterialTheme.colorScheme.background)) {
        ...
    }
}
```

否则深色模式下 `Text` 会默认用黑色，和深色背景混在一起——这是本次修复的深色模式问题之一。

### 5.2 主题系统

`ui/theme/Theme.kt`：

- `ThemeMode`：跟随系统 / 浅色 / 深色；
- `lightScheme(accent)` / `darkScheme(accent)`：以用户主题色为种子，生成一整套 Material 颜色；
- 支持 Android 12+ 动态取色（`dynamicLightColorScheme` / `dynamicDarkColorScheme`）；
- `SideEffect` 设置状态栏/导航栏透明，并切换图标明暗。

所有界面颜色都从 `MaterialTheme.colorScheme` 取，不硬编码白色/黑色（CloudScreen 的蓝色渐变头图除外，它本身是品牌色，文字显式用白色）。

### 5.3 首页 HomeScreen

结构是一个 `LazyColumn`：

```text
渐变头图
├─ Logo / 应用名 / 副标题
├─ 撤销/重做、云同步、设置
├─ 日期
├─ 四宫格：今日安排 / 待办 / 逾期 / 完成率
├─ 完成度进度条
└─ 同步状态文案
搜索入口
筛选 Chip（全部/待办/今天/逾期/已完成）
标签 Chip
任务卡片列表
空状态
```

四宫格用 `Row + weight(1f)`，每个 `HeaderStat` 等宽；窄屏时仍保持一行，不会像固定宽度那样溢出。头图用 `Brush.linearGradient(primary → tertiary)`，文字用 `onPrimary`，保证浅色/深色主题下都可读。

任务卡片 `TaskCard` 显示：

- 左侧色条（事件 color，缺省主题色）；
- 勾选框（点击切换完成）；
- 标题、图标、优先级徽章；
- 截止时间文案（每 30 秒刷新一次 `now`）；
- 标签、附件数。

点击卡片进入详情，长按/编辑按钮进入编辑。

### 5.4 详情 DetailScreen

详情页有两个标签：

```text
详情      元信息 + 状态 + 操作按钮 + Markdown 渲染/源码切换 + 附件
页面与墨迹 PageBoard
```

“详情”标签用 `Column(verticalScroll)`，因为内容是纵向长文；“页面与墨迹”不能再用外层滚动，否则会和页面自身的缩放/平移手势冲突。1.2.0 把它改成：

```kotlin
Box(Modifier.fillMaxSize().padding(...)) {
    PageBoard(
        event = event,
        attachments = event.attachments,
        initialLayout = event.pageLayout,
        resolveFile = vm.repository::resolveAttachment,
        onSave = { vm.updatePageLayout(event.id, it) },
        modifier = Modifier.fillMaxSize(),
    )
}
```

Markdown 默认渲染，右上角可切换“源码”；源码用 `SelectionContainer + Text`，方便复制。

### 5.5 编辑 EditorScreen

编辑页是一个 `Column + verticalScroll`，分为多个 `SectionCard`：

1. 标题；
2. 截止时间、快捷时间（今天 18:00 / 明天 09:00 / 下周一 09:00）；
3. 优先级、位置、提醒分钟；
4. 标签、颜色、图标；
5. 铃声（每事项可选，复制到 `ringtones/`）；
6. 备注（Markdown / 预览 两个 Chip）；
7. 附件（已有附件 + 新建草稿附件）；
8. 取消 / 保存按钮。

状态用 `rememberSaveable(eventId)`，旋转屏幕不丢。`dirty` 标记是否有未保存修改；返回时：

```kotlin
if (dirty) confirmDiscard = true else discardAndClose()
```

新建时附件先放在 `vm.draftAttachments`（`DraftAttachment` 列表），保存拿到新 id 后再调用 `addAttachmentBytes` 落盘；取消时清空草稿。这样不会产生“没有事件的孤儿附件”。

`save()` 的核心：

```kotlin
val newId = vm.saveEvent(
    id = eventId, title = clean, note = note,
    due = if (due > 0) due else null,
    tags = splitTags(tagsText),
    remindBefore = minutes,
    color = color, icon = icon, systemNotify = systemNotify,
    position = if (eventId == null) position else null,
    pageLayout = pageLayout,
)
if (newId != null) {
    pending.forEach { vm.addAttachmentBytes(newId, it.name, it.bytes, it.mime) }
    ...
    onSaved(newId)
}
```

### 5.6 页面 PageBoard

`PageBoard` 是 Android 端最复杂的 Composable，负责“纸张 + 文字 + 图片 + 墨迹 + 缩放/平移”。

#### 5.6.1 页面坐标

页面逻辑尺寸固定为 820 × 1200，和 PC 的 `page_layout` 一致：

```kotlin
private const val PAGE_WIDTH = 820f
private const val PAGE_HEIGHT = 1200f
```

布局时按“适宽”计算缩放比：

```kotlin
val pageWidth = maxWidth
val scale = pageWidth.value / PAGE_WIDTH
```

文字、图片、墨迹的坐标都乘以 `scale` 映射到屏幕 dp。

#### 5.6.2 三种内容层

```text
MarkdownView       文字层（SubcomposeLayout 测量真实高度）
Image              图片层（offset/width/height/graphicsLayer.rotationZ）
Canvas             墨迹层（Path + Stroke）
```

墨迹数据：

```kotlin
private data class InkStroke(
    val color: String,
    val width: Float,
    val points: List<Offset>,
)
```

绘制时把页面坐标乘以 `pxPerUnit = size.width / PAGE_WIDTH`，用 `Path.moveTo/lineTo` 连成折线，`StrokeCap.Round` 让笔画圆润。橡皮擦按点到笔画点的距离删除整笔。

#### 5.6.3 深色模式反相

```kotlin
val darkPage = MaterialTheme.colorScheme.background.luminance() < 0.5f
val pageScheme = if (darkPage) darkScheme(accent) else lightScheme(accent)
val inkColor: (String) -> Color = { hex ->
    val c = parseColor(hex)
    if (darkPage) Color(1f - c.red, 1f - c.green, 1f - c.blue, c.alpha) else c
}
```

- 纸张：浅色 `#FFFEFA` / 深色 `#1E2230`；
- 墨迹：深色模式取 RGB 补色，黑色变白色；
- 文字/表格：页面内部再包一层 `MaterialTheme(colorScheme = pageScheme)`，表格背景、代码块、引用色都跟着切换；

#### 5.6.4 缩放与平移

状态：

```kotlin
var zoom by remember(event.id) { mutableStateOf(1f) }
var pan by remember(event.id) { mutableStateOf(Offset.Zero) }
var viewport by remember { mutableStateOf(IntSize.Zero) }
```

`clampPan` 把平移限制在页面边界内：

```kotlin
fun clampPan(p: Offset, z: Float = zoom): Offset {
    val vw = viewport.width.toFloat()
    val vh = viewport.height.toFloat()
    val pageH = vw * pageUnits / PAGE_WIDTH
    return Offset(
        p.x.coerceIn(minOf(0f, vw - vw * z), 0f),
        p.y.coerceIn(minOf(0f, vh - pageH * z), 0f),
    )
}
```

手势用 `transformable`：

```kotlin
val transformState = rememberTransformableState { zoomChange, panChange, _ ->
    val next = (zoom * zoomChange).coerceIn(1f, 4f)
    val ratio = next / zoom
    zoom = next
    pan = clampPan(
        Offset(
            focal.x + (pan.x - focal.x) * ratio + panChange.x,
            focal.y + (pan.y - focal.y) * ratio + panChange.y,
        ),
        next,
    )
}
```

只在“选择”模式挂 `Modifier.transformable`，墨迹/橡皮模式把事件留给 `Canvas` 的 `pointerInput`，避免“想写字却把页面拖走”。

渲染时用 `graphicsLayer` 做整体缩放，文字、图片、墨迹一起放大，和 PC 的 `Ctrl+Shift+滚轮` 行为一致：

```kotlin
Box(
    Modifier.fillMaxSize().graphicsLayer {
        scaleX = zoom
        scaleY = zoom
        transformOrigin = TransformOrigin(0f, 0f)
    },
)
```

工具栏提供缩小/放大/适宽按钮，并显示当前百分比。

#### 5.6.5 长文本不再被截断

早期页面高度固定为 1200 逻辑单位，长笔记会被裁掉。1.2.0 改为动态测量：

```kotlin
SubcomposeLayout(
    Modifier.width((initial.textW * scale).dp)
        .onSizeChanged { size ->
            val units = size.height * initial.textW / size.width
            if (abs(units - textUnits) > 2f) textUnits = units
        },
) { constraints ->
    val placeable = subcompose("markdown") {
        MarkdownView(markdown = event.note, compact = true)
    }.first().measure(
        Constraints(
            minWidth = constraints.minWidth,
            maxWidth = constraints.maxWidth,
            minHeight = 0,
            maxHeight = Constraints.Infinity,
        ),
    )
    layout(constraints.maxWidth, placeable.height) { placeable.place(0, 0) }
}
```

`SubcomposeLayout` 用无限高度测量 Markdown，得到完整内容高度；再换算回页面坐标：

```text
pageUnits = max(1200, textY + textUnits + 80, 图片最大 y + h + 80)
```

页面高度、平移边界都使用 `pageUnits`，所以长笔记可以一直向下拖，不会再被 1200 截断。

### 6.2 数据库

```sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  email TEXT NOT NULL UNIQUE COLLATE NOCASE,
  display_name TEXT NOT NULL DEFAULT '',
  salt BLOB NOT NULL,
  password_hash BLOB NOT NULL,
  is_admin INTEGER NOT NULL DEFAULT 0,
  is_active INTEGER NOT NULL DEFAULT 1,
  created_at INTEGER NOT NULL,
  last_login_at INTEGER,
  sync_version INTEGER NOT NULL DEFAULT 0,
  sync_updated_at INTEGER,
  sync_size INTEGER NOT NULL DEFAULT 0,
  event_count INTEGER NOT NULL DEFAULT 0,
  attachment_count INTEGER NOT NULL DEFAULT 0,
  sync_summary TEXT NOT NULL DEFAULT '[]',
  tombstones TEXT NOT NULL DEFAULT '{}'
);

CREATE TABLE sessions (
  token_hash TEXT PRIMARY KEY,
  user_id INTEGER NOT NULL,
  kind TEXT NOT NULL,
  csrf TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  expires_at INTEGER NOT NULL,
  ip TEXT NOT NULL DEFAULT '',
  ua TEXT NOT NULL DEFAULT ''
);

CREATE TABLE audit (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  at INTEGER NOT NULL,
  actor TEXT NOT NULL DEFAULT '',
  action TEXT NOT NULL,
  detail TEXT NOT NULL DEFAULT ''
);
```

设计要点：

- `email` 用 `COLLATE NOCASE`，`Foo@x.com` 和 `foo@x.com` 是同一个账号；
- 密码只存 `salt` + `password_hash`，不存明文；
- `sync_version` 是乐观锁版本号，每次上传 +1；
- `sync_summary` 是事件摘要 JSON（id/title/updated_at/attachments），用于客户端判断“变化大不大”，不需要下载整个包；
- `tombstones` 是删除墓碑 JSON（id → 删除时间）；
- `sessions.token_hash` 存 token 的 SHA-256，不存 token 本身，数据库泄露也无法直接登录。

### 6.3 注册与登录

注册：

```python
if not valid_email(email): raise ApiError(400, "请输入有效的邮箱地址")
if len(password) < 8: raise ApiError(400, "密码至少 8 位")
if len(password) > 128: raise ApiError(400, "密码过长")
salt, digest = hash_password(password)
# INSERT users ...
token, _ = make_session(uid, "user", USER_SESSION_TTL, ip, ua)
```

`hash_password`：

```python
def hash_password(password, salt=None):
    salt = salt or os.urandom(16)
    digest = hashlib.pbkdf2_hmac("sha256", password.encode("utf-8"),
                                 salt, PBKDF2_ROUNDS)
    return salt, digest
```

登录：

```python
row = conn.execute("SELECT * FROM users WHERE email=?", (email,)).fetchone()
if not row or not row["is_active"] or not verify_password(password, row["salt"], row["password_hash"]):
    raise ApiError(401, "邮箱或密码不正确")
token, _ = make_session(row["id"], "user", USER_SESSION_TTL, ip, ua)
```

`verify_password` 用 `secrets.compare_digest` 做常量时间比较，避免时序攻击。

限流：

- 注册：同一 IP 每小时 6 次；
- 登录：同一 IP + 邮箱 15 分钟 10 次。

`rate_ok()` 用内存字典记录时间戳窗口，服务重启后清空；对于个人自托管服务足够。

### 6.4 令牌与会话

```python
def make_session(user_id, kind, ttl, ip="", ua=""):
    token = secrets.token_urlsafe(32)
    csrf = secrets.token_urlsafe(24)
    now = int(time.time())
    conn.execute(
        "INSERT INTO sessions(token_hash,user_id,kind,csrf,created_at,expires_at,ip,ua)"
        " VALUES(?,?,?,?,?,?,?,?)",
        (token_hash(token), user_id, kind, csrf, now, now + ttl, ip[:80], ua[:240]),
    )
    return token, csrf
```

客户端拿到的 `token` 只在登录/注册响应里出现一次；服务端只保存 `sha256(token)`。`kind` 区分普通用户会话和管理员会话，避免普通 token 调用管理员接口。

#### 6.5.3 POST /api/sync/upload

请求头：

```text
Authorization: Bearer <token>
X-Moji-Base-Version: 7
X-Moji-Deleted: ["id1","id2"]
Content-Type: application/octet-stream
```

处理流程：

1. 校验 `Base-Version`、`Deleted` 格式、`Content-Length`（默认上限 64 MB）；
2. 把请求体流式写入 `sync/.upload-<id>-<random>.part`；
3. `validate_bundle()` 检查：
   - 是合法 ZIP；
   - 必须有 `manifest.json`；
   - 解压后总大小不超过上限；
   - 条目数不超过 25000；
   - `events` 是数组；
   - 事件 id 非空；
4. 在 `DB_LOCK` 内读取当前 `sync_version`；
5. **不等于 `base_version` → 409**；
6. 原子替换 `sync/<user-id>.mjnote`；
7. 版本 +1，更新摘要、事件数、附件数、大小；
8. 更新墓碑：
   - 本次 manifest 中仍存在的事件 id → 从墓碑中移除；
   - `X-Moji-Deleted` 中且不在 manifest 里的 id → 写入墓碑（当前时间）；
   - 墓碑超过 5000 个时只保留最近 5000 个；
9. 返回新的 meta。

关键代码：

```python
if int(row["sync_version"]) != base_version:
    raise ApiError(409, "云端数据已被其他设备更新，请先下载合并")

target = sync_path(user["id"])
os.replace(tmp, target)
new_version = int(row["sync_version"]) + 1

live_ids = {str(item.get("id")) for item in summary if item.get("id")}
for live_id in live_ids:
    tombstones.pop(live_id, None)
for deleted_id in deleted_ids:
    if deleted_id and deleted_id not in live_ids:
        tombstones[deleted_id] = now
```

`os.replace` 在同一文件系统内是原子的，客户端不会读到半个包。

### 6.6 乐观并发与 409 重试

为什么需要 `base_version`？

假设两台设备都从 v7 开始：

```text
PC     读 meta v7
手机   读 meta v7
手机   上传（base 7）→ 服务端变 v8
PC     上传（base 7）→ 409
```

PC 收到 409 后：

1. 重新 `GET /meta` 得到 v8；
2. 下载 v8 包；
3. 本地 `sync_merge`；
4. 以 base 8 重新上传。

PC 的 `CloudClient` 把 409 映射成 `uploadConflict` 信号；`MainWindow` 收到后重新拉 meta 并重试。Android 在 `performCloudSync` 里用 `for (attempt in 0..2)` 做同样的事，最多重试 2 次。

这不是“最后写入者获胜”，而是“先合并再写”，避免覆盖另一台设备的新数据。

### 6.7 删除墓碑

没有墓碑时会出现：

```text
PC 删除 A → 上传（云端没有 A）
手机本地还有 A → 下次同步把 A 又传回云端
```

解决：客户端记录“上次同步时的 id 集合”，本次上传前算差集：

```text
deleted = last_sync_ids - current_local_ids
```

服务端把这些 id 写入 `tombstones`。另一台设备下载 meta 时拿到墓碑，`apply_tombstones`：

```kotlin
val kept = events.filter { event ->
    val deletedAt = tombstones[event.id]
    deletedAt == null || (event.updatedAt ?: event.createdAt ?: 0L) > deletedAt
}
```

只有“本地在删除之后没有更新过”的记录才会被删；如果本地刚改过，保留本地，下一次上传会把墓碑清掉（因为 live_ids 包含它）。

### 6.11 安全设计小结

| 风险 | 措施 |
| --- | --- |
| 密码泄露 | PBKDF2-HMAC-SHA256 + 随机盐，不存明文 |
| 数据库泄露 | 只存 token 的 SHA-256，不存 token 原文 |
| 暴力登录 | IP + 邮箱限流 |
| CSRF | 管理后台表单带 CSRF token |
| 恶意 ZIP | 限制条目数、解压大小、manifest 大小 |
| 路径穿越 | 附件路径 canonical 检查；ZIP 内文件名过滤 |
| 并发覆盖 | `X-Moji-Base-Version` 乐观锁 + 409 重试 |
| 删除复活 | 墓碑 + `last_ids` 差集 |
| 公网暴露 | 只监听 Tailscale 地址；SSH 隧道用受限密钥 |

## 8. 关键设计取舍

1. **为什么用链表而不是 `std::vector`？**
   课程要求练习链表，且“位置即优先级”让插入/删除的语义非常直观；代价是查找 O(n)，但对记事本规模足够。Android 端为了 Compose 的不可变状态，改用 `List + reindex`，但保留了同样的不变量。

2. **为什么用 JSON 文本而不是 SQLite？**
   PC 和 Android 要共享同一份数据，JSON 可读、可 diff、可直接放进 `.mjnote`；附件用目录而不是 BLOB，便于用户直接打开。云服务端才用 SQLite 存账号和元信息。

3. **为什么删除不立即删附件？**
   删除事项时只删索引，附件留在磁盘，配合撤销/墓碑可以恢复；定期 `gc_orphans()` 清理没有事件引用的目录。

4. **为什么云同步传整包而不是增量？**
   个人记事本数据量小（通常几 MB），整包实现简单、天然一致；用 `meta.summary` 避免不必要的下载，用 `base_version` 避免覆盖。

5. **为什么 Android 页面用 820×1200 固定坐标？**
   与 PC 的 `page_layout` 完全一致，墨迹、图片位置可以跨端还原；屏幕适配只在渲染时乘一个 `scale`，数据不随设备变化。

6. **为什么深色模式要“页面反相”而不是简单换背景？**
   墨迹颜色是用户选的（黑、蓝、红），深色纸上黑墨不可见。反相把黑色变白、彩色取补色，同时文字/表格用页面自己的 Material 配色，保证可读性。
