# 设计说明（C++17 主实现）

本文对应课程设计“设计要求”的四点：数据结构、文件格式、函数原型、容错处理，并补充 UI 与测试说明。

---

## 1. 总体架构

```
┌────────────────────────────────────────────────────────────┐
│  CLI (src/main.cpp)   TUI (src/tui/tui.cpp)   GUI (src/gui) │
└───────────────────────────┬────────────────────────────────┘
                            ▼
                 ┌─────────────────────┐
                 │    Repository       │  增删改查、查询、撤销、附件、合并
                 └──────┬──────┬───────┘
                        │      │
          ┌─────────────▼─┐  ┌─▼──────────────┐
          │  EventList    │  │  importer      │
          │  优先级链表    │  │ json/mjnote/   │
          └───────┬───────┘  │ todo.txt/md    │
                  │          └────────────────┘
          ┌───────▼──────────────────────────┐
          │             Store                │  文本文件、附件、备份、快照
          └──────────────────────────────────┘
```

- 核心 `src/core` 不依赖 GUI/TUI，也不依赖 Qt；只用 C++17 标准库 + nlohmann/json。
- TUI/GUI 只调用 `Repository`，共享同一份数据与行为。
- 写操作立即落盘；失败抛 `RepoError`/`StoreError`，由 UI 转成状态提示。

## 2. 数据结构

### 2.1 `Event`

```cpp
struct Event {
    std::string id;                 // 8 位十六进制
    std::string title;              // 必填
    std::string note;               // 多行 Markdown 纯文本
    std::optional<std::time_t> due; // 无期限为空
    int priority = 1;               // 1 起始，等于链表位置
    bool done = false;
    std::optional<std::time_t> done_at;
    std::vector<std::string> tags;
    std::vector<Attachment> attachments;
    std::optional<std::time_t> created_at, updated_at;
    int remind_before = 0;          // 提前分钟
    bool system_notify = false;     // 到点另外发 Windows 系统通知
    std::optional<std::time_t> last_reminded_at;
    std::string color;              // GUI 色条
    std::string icon;               // 自定义图标（emoji/字符）
    std::string page_layout;        // OneNote 页面布局 + 墨迹 JSON
    // 导入打包文件时的临时附件数据，不参与序列化
    std::vector<std::pair<std::string, Bytes>> pending_attachments;
};
```

`Attachment`：`path`（相对数据目录）、`name`、`mime`、`size`、`added_at`；`is_image()` / `is_audio()` 由 MIME 判断。

### 2.2 优先级单向链表

```cpp
class EventList {
    struct Node { Event event; Node* next; };
    Node* head_ = nullptr;
    Node* tail_ = nullptr;
    size_t size_ = 0;
public:
    Event& append(Event);
    Event& insert_at(int pos, Event);   // 顺延核心
    std::optional<Event> remove(const std::string& id);
    bool move_to(const std::string& id, int pos);
    void reindex();
    Event* find(const std::string& id);
    int index_of(const std::string& id) const;
};
```

不变量：

1. 任意时刻 `event.priority == 从 1 开始的位置序号`；
2. 在 `pos` 插入后，原 `pos..n` 全部 +1；
3. 删除后，后续节点整体 -1；
4. 序列化按链表顺序，读取后按 `(priority, created_at)` 稳定排序再 `reindex()`。

复杂度：

| 操作 | 复杂度 |
| --- | --- |
| 追加 | O(n)（找尾，n 通常 < 1000） |
| 按 id 查找 | O(n) |
| 按位置插入 | O(n) 找前驱 + O(n) 重编号 |
| 删除 / 移动 | O(n) |

## 3. 文件格式

### 3.1 `events.json`

UTF-8、缩进 2 空格、按优先级排序：

```json
{
  "app": "moji-note",
  "version": 1,
  "count": 2,
  "events": [
    {
      "id": "59535cd3",
      "title": "提交课程设计报告",
      "note": "## 清单\n- [x] 核心功能",
      "due": "2026-11-23T18:00:00",
      "priority": 1,
      "done": false,
      "done_at": "",
      "tags": ["课程", "截止"],
      "attachments": [
        {"path": "attachments/59535cd3/cover.bmp", "name": "cover.bmp",
         "mime": "image/bmp", "size": 172854, "added_at": "2026-11-23T13:00:00"}
      ],
      "created_at": "2026-11-23T12:00:00",
      "updated_at": "2026-11-23T12:00:00",
      "remind_before": 60,
      "last_reminded_at": "",
      "color": "#5b8def"
    }
  ]
}
```

选择理由：可读、可 diff、可手工修复；附件二进制独立存放，避免 JSON 膨胀。

### 3.2 目录布局

| 路径 | 作用 |
| --- | --- |
| `events.json` | 主数据 |
| `events.json.bak` | 上一次成功保存 |
| `backups/events-*.json` | 每次保存自动备份，保留 20 份 |
| `backups/undo-*.json` | CLI 写操作前快照（跨进程撤销） |
| `backups/redo-*.json` | 撤销前快照 |
| `config.json` | 主题等 |
| `attachments/<event-id>/` | 附件 |

### 3.3 `.mjnote`

**store 方式 ZIP**（不压缩）：

```
manifest.json
files/<event-id>/<i>_<name>
```

`manifest.json` 与 `events.json` 类似，附件条目增加 `"src": "files/..."`。导入时：

1. `zip_read` 解出所有条目；
2. 逐条 `Event::from_json`，跳过坏记录；
3. 附件字节放进 `Event::pending_attachments`；
4. `Repository::import_events` 去重、分配新 id；
5. 回调中 `Store::add_attachment_bytes` 落盘并改写路径；
6. 重新编号并保存。

ZIP 实现只支持 method 0（store），写入 UTF-8 文件名标志；足够自产自读，不引入 zlib 依赖。

### 3.4 todo.txt

```
(A) 2026-11-23 提交课程设计报告 due:2026-11-23T18:00 +课程 +截止
x 2026-11-22 2026-11-21 完成服务器巡检 +运维
```

导入时在任意 token 位置识别 `(A)`、`due:`、`+tag`、日期，兼容常见 todo.txt 工具。

### 3.5 C 版 `notes.dat`

```
# MOJI-C 1
1|1|2026-11-24 18:00|0|买牛奶|超市采购
```

## 5. 关键流程

### 5.1 新增 / 插入

```
UI 收集字段
  → Repository::add(position)
      → Event::create
      → EventList::append / insert_at
      → reindex
      → Store::save_events（原子写 + 备份）
  → 下一帧重新查询刷新
```

### 5.2 提醒

```
TUI：每 900ms 输入超时时 / GUI：每帧检查，30 秒一次
  Repository::due_reminders(now)
    → Event::needs_reminder:
         not done &&
         now >= due - remind_before &&
         last_reminded_at 早于本轮提醒点
  → MessageBeep / 弹窗 / TUI 提醒条
  → 若 Event.system_notify：QSystemTrayIcon::showMessage 系统通知
  → mark_reminded 落盘
```

### 5.3 撤销

- TUI/GUI：内存中的 `undo_` / `redo_` 快照栈（最多 60 步），每次写操作前压栈。
- CLI：每个进程独立，写操作前把 `events.json` 复制到 `backups/undo-*.json`；`moji undo` 恢复最近快照，并把当前状态存到 `redo-*`。
- 删除不立即删除附件文件，保证撤销后仍可打开；`gc_orphans()` 可回收。

### 5.4 GUI 自动保存

编辑器缓冲区（标题/截止/提醒/标签/备注）任一变化 → `dirty=true`，记录时间；超过 0.7 秒无输入 → `save_current()`。切换选事、关闭窗口时强制保存。

## 6. 容错与校验

| 层 | 措施 |
| --- | --- |
| 输入 | 标题非空、时间格式、提醒非负、位置范围、标签清洗 |
| 模型 | `from_json` 缺字段给默认值；非法附件跳过；done/done_at 同步 |
| 存储 | 临时文件 + `MoveFileExW` 原子替换；`.bak` 回退；损坏文件隔离；备份轮转；路径穿越校验 |
| 业务 | 撤销/重做；删除确认；附件延迟清理；导入去重；未知字段拒绝 |
| UI | 状态提示；保存失败阻止关闭；外部修改检测（TUI）；表单校验 |

## 7. UI 设计

### 7.1 TUI

- Win32 控制台：保存/恢复模式，alternate screen，ANSI 真彩色。
- 布局：顶栏（品牌 + “电子记事本 · TUI” + 时钟）→ 44 列侧栏（今日/逾期、待办/完成、带边框搜索框、筛选、任务两行一项、底部提示）→ 详情（标题、元信息、分隔线、Markdown 备注/表格、附件）→ 底栏快捷键。与 Python 原型 TUI 保持一致。
- 交互：方向键、`Space`、字母快捷键；鼠标点击左侧方框勾选；`/` 进入内联搜索框（直接输入，Enter 确认，Esc 清空）；中文输入表单使用 cooked 模式。
- 弹层：`?` 居中帮助面板（快捷键表格 + 关闭按钮）；`o` 附件弹窗（↑↓ 选择、Enter 打开、Del 移除、Esc 关闭）；弹层用 ANSI 绝对定位覆盖主界面。
- 表格：`build_detail` 识别 `| a | b |` + `| --- | --- |`，按显示宽度计算列宽、必要时压缩，绘制 `┌┬┐` / `├┼┤` / `└┴┘` 框线。
- 提醒：900ms tick；到点响铃 + 黄色提醒条，15 秒后消失；外部文件变化自动重载。

### 7.2 GUI

- Qt6 Widgets + QSS，Fusion 风格；Material 观感：圆角 12、主色 `#4f6ef7`（浅）/`#7c9cff`（深）、卡片色条、chips。
- 三栏：252px 侧栏 / 420px 列表 / 自适应详情，QSplitter 可调；详情默认收起，启动不预读卡片。
- 详情两种状态：只读页面（标题、元信息、OneNote 页面、附件）和编辑表单；点击卡片进入只读页面，右上角「✎ 编辑」进入表单，编辑顶栏「完成」返回，`✕` 关闭分屏。
- 字体：微软雅黑 UI；标题 21px、卡片标题 10.8pt、辅助 9pt。
- 备注三页：编辑（Markdown 源码 + B/I/U/S/颜色/表格）、预览（`markdown.cpp` 渲染）、页面（OneNote 风格）。
- 页面：`page_view.cpp` 的 QGraphicsScene，文本层 + 图片层 + 墨迹层；工具栏为 MD 胶囊按钮「选择 / 墨迹 / 橡皮 / 颜色 / 粗细 / 撤销 / 清空 / 加图 / 置顶 / 置底 / 删图」，工具用 QButtonGroup 互斥；图片可拖动/缩放/旋转/置顶置底/删除；墨迹用 QPainterPath 画在页面上。
- 只读页面复用同一个 PageEditor，调用 `set_read_only(true)` 隐藏工具栏并禁用图元拖动/选择。
- 提醒：编辑界面事项级复选框「提醒时使用 Windows 系统通知」；`QSystemTrayIcon` 常驻，到点调用 `showMessage` 发系统通知。
- 附件：QImage/QPixmap 读取图片缩略图；双击打开、右键移除、拖入排序；剪贴板粘贴；页面图片。
- 主题色：`make_light/make_dark` 由 accent 派生 primary/primarySoft；TUI 主题由 `tui-theme.json` 控制配色、侧栏宽度、提示与终端字体。
- 多选：Ctrl 切换、Shift 范围、Ctrl+Shift 追加，批量完成/删除。
- 截图模式：`WA_DontShowOnScreen` + `QWidget::grab()`，不弹窗但使用真实字体。
- 窗口版 `moji-gui.exe` 由 qmake `CONFIG += windows` 生成，无控制台；`moji.exe gui` 通过启动器拉起它。

## 9. 取舍说明

1. **为什么用 store 方式 ZIP**：避免给课程项目引入 zlib；`.mjnote` 仍是一个标准 ZIP，可用任意解压工具打开。
2. **为什么 GUI 用 Qt6 Widgets**：课程鼓励 Qt/MFC；Qt 的布局系统能避免自绘 UI 的文字形变，QSS 也便于做 MD 风格；Qt 本身跨平台。代价是需要安装 Qt6 运行库，`windeployqt` 体积较大。
3. **为什么 TUI 自己写而不是用现成库**：直接控制 Win32 Console 的鼠标/键盘/中文输入；依赖最少。
4. **为什么附件不立即删除**：为撤销保留文件；孤儿目录由 `gc_orphans` 清理。
5. **为什么保留 Python 原型**：交互验证与附件排序等实现可对照移植；但最终提交以 C++ 为准。
