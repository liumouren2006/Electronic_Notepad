# 墨记 MoJi · Android 构建说明

本文记录 Android 客户端从零搭建工具链、编译、测试、安装的完整过程。
所有命令均在 Windows 11 + Git Bash 下验证。

## 2. 安装 JDK

任选一种：

1. **已有 Android Studio / JetBrains IDE**：可直接使用其自带 JBR，例如
   `D:\JetBrains Rider 2025.2.2\jbr`，无需单独安装。
2. **Temurin 17**：从 <https://adoptium.net/> 或国内镜像下载 Windows x64 ZIP，
   解压到 `D:\Java\temurin-17`，确保存在 `bin\java.exe` 与 `bin\javac.exe`。
3. **Microsoft OpenJDK 17**：<https://aka.ms/download-jdk/microsoft-jdk-17.0.13-windows-x64.zip>。

验证：

```bash
export JAVA_HOME='D:\JetBrains Rider 2025.2.2\jbr'   # 换成自己的路径
"$JAVA_HOME/bin/java" -version
"$JAVA_HOME/bin/javac" -version
```

> 注意：仅解压了一半的 JDK 目录可能缺少 `bin\server\jvm.dll`，表现为执行
> `java.exe` 直接返回 127 / 无输出。请确认安装完整。

## 3. 安装 Android SDK

### 3.1 下载 command-line tools

```bash
mkdir -p /d/tools/moji-build
cd /d/tools/moji-build
curl -L --retry 5 -o cmdline-tools.zip \
  "https://dl.google.com/android/repository/commandlinetools-win-11076708_latest.zip"
```

解压到 SDK 约定位置（必须是 `cmdline-tools/latest`）：

```bash
mkdir -p /d/Android/sdk/cmdline-tools
unzip -q -o cmdline-tools.zip -d /d/Android/sdk/cmdline-tools
mv /d/Android/sdk/cmdline-tools/cmdline-tools /d/Android/sdk/cmdline-tools/latest
```

### 3.2 接受许可并安装组件

```bash
export JAVA_HOME='D:\JetBrains Rider 2025.2.2\jbr'
yes | cmd //c 'D:\Android\sdk\cmdline-tools\latest\bin\sdkmanager.bat --licenses'
cmd //c 'D:\Android\sdk\cmdline-tools\latest\bin\sdkmanager.bat platform-tools platforms;android-35 build-tools;35.0.0'
```

验证：

```bash
ls /d/Android/sdk/platforms/android-35
ls /d/Android/sdk/build-tools/35.0.0
```

### 3.3 让 Gradle 找到 SDK

工程根目录 `local.properties`：

```properties
sdk.dir=D:/Android/sdk
```

> 该文件与机器相关，不建议提交到版本库；换机器后重新生成即可。
> 也可使用反斜杠 `D\:\\Android\\sdk`。

## 4. Gradle

### 4.1 使用 Wrapper（推荐）

工程已包含 `gradlew` / `gradlew.bat` 与 `gradle/wrapper/`。
`gradle-wrapper.properties` 的下载地址使用腾讯云镜像，避免 `services.gradle.org` 直连超时：

```properties
distributionUrl=https\://mirrors.cloud.tencent.com/gradle/gradle-8.9-bin.zip
```

首次构建会下载约 130 MB 的 Gradle 发行包到 `%USERPROFILE%\.gradle\wrapper\dists`。

### 4.2 使用本地 Gradle（离线/内网）

```bash
export JAVA_HOME='D:\JetBrains Rider 2025.2.2\jbr'
/d/tools/moji-build/gradle-8.9/bin/gradle :app:assembleDebug --console=plain
```

> 生成/更新 wrapper 时，如果 `services.gradle.org` 不可达，Gradle 会校验失败。
> 使用镜像参数即可：
> `gradle wrapper --gradle-distribution-url https://mirrors.cloud.tencent.com/gradle/gradle-8.9-bin.zip`

### 4.3 依赖镜像

`settings.gradle.kts` 已把阿里云 Maven 镜像放在 `google()` / `mavenCentral()` 之前：

- `https://maven.aliyun.com/repository/google`
- `https://maven.aliyun.com/repository/gradle-plugin`
- `https://maven.aliyun.com/repository/central`
- `https://maven.aliyun.com/repository/public`

在无 Google Maven 直连的环境下仍可解析 AGP、AndroidX、Compose 依赖。

## 5. 编译

```bash
cd "D:/程序设计/moji-android"
export JAVA_HOME='D:\JetBrains Rider 2025.2.2\jbr'

# 调试包
./gradlew :app:assembleDebug --console=plain

# 或使用本地 Gradle
/d/tools/moji-build/gradle-8.9/bin/gradle :app:assembleDebug --console=plain
```

首次构建需要下载 AGP / Kotlin / Compose / AndroidX 依赖（约数百 MB，视缓存而定）；
增量构建通常在 30 秒内完成。

产物：

```
app/build/outputs/apk/debug/app-debug.apk
```

查看包信息：

```bash
/d/Android/sdk/build-tools/35.0.0/aapt2.exe dump badging \
  app/build/outputs/apk/debug/app-debug.apk | head -20
```

### 5.1 中文路径说明

AGP 默认拒绝非 ASCII 工程路径，会报：

```
Your project path contains non-ASCII characters...
```

本工程在 `gradle.properties` 中显式关闭该检查：

```properties
android.overridePathCheck=true
```

APK 构建可以正常完成。但 Gradle 的 **单元测试 worker** 在中文路径下仍可能出现
classpath 编码问题（`ClassNotFoundException`），见第 7 节。

## 6. 安装到手机

### 方式 A：adb

```bash
/d/Android/sdk/platform-tools/adb.exe devices
/d/Android/sdk/platform-tools/adb.exe install -r \
  "D:/程序设计/moji-android/app/build/outputs/apk/debug/app-debug.apk"
```

### 方式 B：直接传文件

把 `app-debug.apk` 发到手机（QQ / 微信 / 数据线均可），在文件管理器中点击安装。
首次安装需允许「安装未知来源应用」。

### 首次启动

- Android 13+ 会请求通知权限；拒绝后可在「设置 → 提醒 → 授权」重新申请。
- 若系统限制精确闹钟，提醒会自动降级为普通闹钟；每 15 分钟的 WorkManager 扫描兜底。
- 建议在「设置 → 与 PC 端同步」中选择包含 `events.json` 的目录，并完成一次「拉取」或
  「双向同步」。

## 7. 测试

### 7.1 运行单元测试

```bash
cd "D:/程序设计/moji-android"
./gradlew :app:testDebugUnitTest --console=plain
```

当前 10 项 JVM 测试通过（`DataFormatTest` 9 项 + 云同步联调 1 项；前者默认全跑，后者需设置 `MOJI_CLOUD_TEST=1`）。

### 7.2 中文路径下测试报 ClassNotFoundException

**现象**：

```
DataFormatTest > initializationError FAILED
java.lang.ClassNotFoundException: com.moji.note.DataFormatTest
```

测试类已编译到 `app/build/tmp/kotlin-classes/debugUnitTest/`，但测试 worker 无法加载。
原因为工程路径包含中文时 Gradle 8.9 测试进程的 classpath 编码问题（与代码无关，
`assembleDebug` 不受影响）。

**解决**：把工程复制到纯 ASCII 路径后运行测试，例如：

```bash
rm -rf /d/moji-test && mkdir -p /d/moji-test
cd "D:/程序设计/moji-android"
tar --exclude=.gradle --exclude=build --exclude='app/build' -cf - . | tar -C /d/moji-test -xf -
cd /d/moji-test
./gradlew :app:testDebugUnitTest
```

Gradle 依赖缓存是全局共享的，复制后无需重新下载依赖。

### 7.3 真实 PC 数据兼容性回归

可把 PC 的 `%USERPROFILE%\.moji\events.json` 与 `attachments/` 复制到临时工程，
用 `MjnoteCodec` / `MojiJson` 做解析、重写、打包、解包验证。本次已执行：

- 7 条真实记录（含图片附件、空截止时间、自定义字段）解析成功
- 重写后的 `events.json` 再次解析，标题 / 优先级 / 附件数量一致
- `.mjnote` 打包后再解包，附件数量一致
- 生成的 ZIP 首条目为 `manifest.json`，全部条目 method = 0（STORED），符合 PC `zip.cpp` 约束

## 8. 发布签名（可选）

调试包已可直接安装。若需要正式签名：

```bash
keytool -genkeypair -v -keystore moji-release.jks -alias moji \
  -keyalg RSA -keysize 2048 -validity 10000
```

在 `app/build.gradle.kts` 中增加 `signingConfigs` 并应用到 `release`，然后：

```bash
./gradlew :app:assembleRelease
```

> 不要 把 keystore 和密码提交到仓库。

## 9. 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| `Failed to apply plugin 'com.android.application'` 且提示 non-ASCII path | 确认 `gradle.properties` 含 `android.overridePathCheck=true` |
| 依赖下载 403 / 超时 | 检查阿里云镜像顺序；公司网络可能需要代理；`gradle --refresh-dependencies` |
| `Unsupported class file major version` | 使用了过新的 JDK 跑旧 Gradle；改用 JDK 17/21 并把 `JAVA_HOME` 指向完整 JDK |
| `java.exe` 返回 127 / 无输出 | JDK 解压不完整（缺 `bin/server/jvm.dll`），重新解压 |
| SDK license not accepted | 重新执行 `sdkmanager --licenses`，全部输入 `y` |
| 找不到 `platforms/android-35` | 重新执行 `sdkmanager "platforms;android-35"` |
| Gradle wrapper 下载失败 | 修改 `gradle-wrapper.properties` 为腾讯云镜像，或改用本地 Gradle |
| 单元测试 `ClassNotFoundException` | 中文路径限制，复制到 ASCII 路径运行测试 |
| 通知不显示 | Android 13+ 未授予通知权限；到「设置 → 提醒」授权 |
| 提醒时间不精确 | 系统禁止精确闹钟；可在系统设置允许「闹钟和提醒」，否则自动降级 |
| 同步目录失效 | 部分文件管理器会回收 SAF 权限；重新选择目录并授予持久权限 |
| PC 与手机同时改同一份数据 | 最后一次写入覆盖；请避免 PC 端在同步期间编辑，或使用双向同步前先拉取 |
| 图片附件打不开 | 文件已被移动/删除；附件路径相对数据目录，导入 `.mjnote` 时会重建 |
